# 🏦 PostgreSQL Banking System (High-Load & Fault-Tolerant)

Профессиональная реализация ядра банковской системы на базе **PostgreSQL** и **Golang**.
Проект демонстрирует решение критических проблем конкурентного доступа, масштабирования данных и обеспечения целостности баланса.

---

## 🚀 Основные возможности (Key Features)

### 🛠 Архитектура и масштабируемость

* **Партиционирование транзакций (Table Partitioning):**

  * Таблица `transactions` переведена на схему `PARTITION BY RANGE (created_at)`
  * Данные автоматически распределяются по ежемесячным физическим партициям
    *(например, `transactions_2026_03`)*
  * Использование **Default Partition** для предотвращения ошибок при выходе за границы диапазонов
  * **Результат:**

    * мгновенный поиск по датам
    * возможность удаления старых архивов без нагрузки на БД

* **Оптимистичная блокировка (Optimistic Locking):**

  * Реализована версия перевода (**v5**) через проверку колонки `version` в таблице `accounts`
  * Использование оператора `GET DIAGNOSTICS` для контроля `ROW_COUNT` в процедурах
  * **Результат:** высокая пропускная способность (**High Throughput**) за счёт отказа от тяжёлых блокировок строк

---

### 🛡 Безопасность и контроль транзакций

* **Защита от дедлоков (Deadlock Prevention):**

  * Алгоритм принудительной сортировки UUID перед выполнением `FOR UPDATE`
  * Гарантия одинакового порядка блокировок *(от меньшего ID к большему)*

* **Аудит и логирование:**

  * Автоматическая система логов через триггерную функцию `audit_trigger_func`
  * Каждое изменение баланса фиксируется с меткой времени

* **Бизнес-ограничения (Constraints):**

  * Запрет отрицательного баланса:

    ```sql
    CHECK (balance >= 0)
    ```
  * Уникальность пары **Клиент + Валюта**
    *(индекс + ограничение на уровне таблицы)*

---

### ⚙️ Прикладной уровень (Golang CLI)

* **Retry-механизм:**

  * Автоматические повторы *(до 5 попыток)* при ошибках:

    * `40001` — Serialization Failure
    * `40P01` — Deadlock Detected

* **External Transaction Management:**

  * Управление транзакциями вынесено в приложение
  * Используется `pgx/v5.BeginFunc`

---

## 📊 Исследование уровней изоляции

В проекте реализованы SQL-сценарии для тестирования поведения БД под нагрузкой:

1. **Read Committed**

   * Базовая изоляция
   * Защита от "грязного" чтения

2. **Repeatable Read**

   * Ошибки сериализации при параллельных изменениях

3. **Serializable**

   * Построение полностью консистентных отчётов
     *(например, общая сумма средств в банке)*

## 💻 Инструкция по запуску

### 1. Развертывание базы

```bash

```

---

### 2. Подготовка Go-зависимостей

```bash
go mod init pg-banking-system
go get github.com/jackc/pgx/v5
```
