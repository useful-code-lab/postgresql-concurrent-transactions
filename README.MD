2. Оптимистическая блокировка (Optimistic Locking)
Это альтернатива FOR UPDATE. Вместо того чтобы «вешать замок» и заставлять других ждать, мы добавляем в таблицу accounts колонку version INT.
Логика: При обновлении мы пишем SET balance = ..., version = version + 1 WHERE id = ... AND version = 10.
Результат: Если кто-то успел изменить строку, пока мы считали данные, version изменится, и наш UPDATE затронет 0 строк. Это работает быстрее пессимистических блокировок в системах, где конфликты редки.
3. Партиционирование таблицы транзакций
В реальном банке таблица transactions растет на миллионы строк в день. Обычные индексы начинают тормозить.
Что сделать: Пересоздайте таблицу transactions как Partitioned Table по дате (PARTITION BY RANGE (created_at)). Это позволит базе мгновенно удалять старые архивы и быстро искать переводы за конкретный день.
